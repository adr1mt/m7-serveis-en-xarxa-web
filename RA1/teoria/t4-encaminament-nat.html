Encaminament i NAT

Convertir el servidor en la porta d'enllaç que dona Internet als seus clients.

Què sabràs fer en acabar

  • Explicar per què un client amb IP correcta encara no té Internet.
  • Activar l'encaminament de paquets de forma permanent.
  • Configurar NAT amb nftables.
  • Comprovar on falla la connexió quan no funciona.

Tinc IP, però no tinc Internet

El client ha rebut la seva configuració per DHCP i la porta d'enllaç apunta al teu servidor. Fa ping a Internet i no passa res. DHCP ha funcionat perfectament: el que falla és el pas següent.

Perquè aquell paquet arribi a Internet i torni, calen dues coses:

  • Encaminament — que el servidor accepti passar paquets d'una targeta a l'altra.
  • NAT — que canviï l'adreça d'origen per la seva, perquè la resposta sàpiga tornar.

Cap de les dues està activada per defecte a Linux. Les has d'activar tu.

Encaminament: deixar passar els paquets

Un Linux amb dues targetes de xarxa no reenvia res entre elles. Per seguretat, ve desactivat de fàbrica: si no ho actives, cada targeta viu la seva vida.

L'interruptor és un únic valor del nucli, que pots consultar així:

cat /proc/sys/net/ipv4/ip_forward

Si respon 0, està desactivat. Amb 1, el servidor ja fa d'encaminador (router) entre les seves xarxes.

NAT: qui signa la carta

Els clients tenen adreces privades, per exemple 192.168.1.50. Aquestes adreces no existeixen a Internet: cap servidor de fora sabria com respondre-hi.

NAT (Network Address Translation) ho resol canviant l'adreça d'origen del paquet per la del servidor abans d'enviar-lo, i apuntant-se qui l'havia demanat. Quan arriba la resposta, la torna al client correcte.

És el mateix que fa el router de casa teva amb tots els mòbils i ordinadors: de portes enfora, tots surten amb una única adreça. La variant que farem servir s'anomena masquerade.

Una regla mal escrita et tanca la porta

Estàs escrivint un tallafoc. Si poses policy drop a la cadena input sense permetre SSH, perdràs la connexió en carregar les regles. En aquesta pràctica deixem input amb policy accept justament per evitar-ho: filtrem el trànsit que travessa el servidor, no el que hi arriba.

Convertir el servidor en porta d'enllaç

  1. Mira com està ara l'encaminament:

    cat /proc/sys/net/ipv4/ip_forward

    Sortirà 0.

  2. Activa'l de manera permanent amb un fitxer propi, que és més net que tocar el fitxer general:

    echo "net.ipv4.ip_forward=1" | sudo tee /etc/sysctl.d/99-encaminament.conf
sudo sysctl --system

    Torna a comprovar-ho: ara ha de sortir 1. I sobreviurà a un reinici.

  3. Escriu les regles de tallafoc i NAT:

    sudo nano /etc/nftables.conf

    Deixa el fitxer amb aquest contingut, canviant els noms de les targetes pels teus:

    #!/usr/sbin/nft -f
flush ruleset

table inet filter {
    chain input {
        type filter hook input priority 0;
        policy accept;
    }
    chain forward {
        type filter hook forward priority 0;
        policy drop;

        # de la xarxa interna cap a Internet
        iif "enp2s0" oif "enp1s0" accept

        # només les respostes de tornada
        iif "enp1s0" oif "enp2s0" ct state related,established accept
    }
    chain output {
        type filter hook output priority 0;
        policy accept;
    }
}

table ip nat {
    chain postrouting {
        type nat hook postrouting priority 100;
        # NAT a la targeta que surt a Internet
        oif "enp1s0" masquerade
    }
}

  4. Activa el servei perquè carregui les regles ara i a cada arrencada:

    sudo systemctl enable --now nftables
    Compte enable --now fa les dues coses alhora. No facis enable & start amb un sol &: això envia la primera comanda a segon pla i sembla que funciona quan no ho ha fet.

  5. Comprova que les regles s'han carregat:

    sudo nft list ruleset

    Ha de sortir exactament el que has escrit. Si surt buit, hi ha un error de sintaxi al fitxer.

  6. Prova-ho des del client, per capes, en aquest ordre:

    ip route              # la porta d'enllaç és el servidor?
ping -c3 192.168.1.1  # arribo al servidor?
ping -c3 9.9.9.9      # surto a Internet?
ping -c3 www.upc.edu  # funciona el DNS?

    La gràcia és l'ordre: la primera que falli et diu exactament on és el problema. No cal endevinar res.

Ubuntu 26.04 nftables i sysctl funcionen igual a 24.04 i 26.04. Comprova sempre la sortida real de la teva màquina.

Per què no fem servir iptables

Tota la documentació d'Internet parla d'iptables, amb comandes com iptables -t nat -A POSTROUTING -o enp1s0 -j MASQUERADE. Encara funcionen, però és una capa de compatibilitat: per sota, avui, hi ha nftables.

nftables és el sistema de tallafoc de Linux des de fa anys i el que trobaràs a qualsevol servidor nou. Té una sintaxi unificada i les regles es desen en un fitxer que pots llegir i versionar.

No barregis els dos. Si escrius regles amb iptables i les consultes amb nft list ruleset les veuràs traduïdes, i al revés no. Tria un i queda-t'hi.

Criteris professionals

  • policy drop a forward i obre només el que cal. El que no s'ha permès, no passa.
  • Fes servir ct state related,established per al trànsit de tornada, en lloc d'obrir el sentit contrari sencer.
  • Configuració permanent, no de sessió. Un sysctl -w o un nft add rule desapareixen en reiniciar.
  • Activa NAT només a la targeta externa. Un masquerade a la interna amaga qui és qui i complica qualsevol diagnòstic.
  • Prova per capes (ruta → servidor → IP externa → nom) abans de tocar res.

Errors habituals

Funcionava i després de reiniciar ja no

Causa Ho vas activar només per a la sessió: amb sysctl -w o afegint regles a mà.

Solució El fitxer a /etc/sysctl.d/ i les regles a /etc/nftables.conf, amb el servei habilitat.

nft list ruleset surt buit

Causa Error de sintaxi al fitxer: el flush ruleset s'executa i la resta falla.

Solució sudo nft -c -f /etc/nftables.conf comprova el fitxer sense aplicar-lo i et diu la línia.

El client arriba al servidor però no a Internet

Causa Falta l'encaminament o falta el NAT.

Solució Comprova cat /proc/sys/net/ipv4/ip_forward i que la taula nat apareix a nft list ruleset.

ping 9.9.9.9 va, però ping www.upc.edu no

Causa L'encaminament i el NAT funcionen. El problema és el DNS que reparteix el teu servidor DHCP.

Solució Revisa domain-name-servers al fitxer de Kea i, al client, resolvectl status.

Resum

  • Un client amb IP correcta encara necessita encaminament i NAT per sortir a Internet.
  • L'encaminament s'activa amb net.ipv4.ip_forward=1, permanent a /etc/sysctl.d/.
  • El NAT es fa amb masquerade a la targeta externa, dins de /etc/nftables.conf.
  • Es fa servir nftables, no iptables. I mai els dos alhora.
  • Per diagnosticar, prova per capes: ruta, servidor, IP externa, nom.
