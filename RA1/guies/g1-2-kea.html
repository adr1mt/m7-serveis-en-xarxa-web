Guia: Kea

El servidor DHCP: instal·lació, rang, opcions i reserves.

Què hi ha en aquesta guia

Documentació oficial: kea.readthedocs.io

  • La targeta interna ha de tenir IP fixa abans de començar: guia G1.1.
  • Només cal el servei d'IPv4, kea-dhcp4-server.

Per què Kea i no una altra cosa

Durant vint anys, el servidor DHCP de Linux va ser isc-dhcp-server. La fundació que el mantenia el va donar per acabat el 2022 i el va substituir per Kea, del mateix equip. És el que ve als repositoris d'Ubuntu i el que trobaràs a les empreses.

Si busques per Internet, veuràs molta documentació d'isc-dhcp-server amb una sintaxi diferent. No et serveix. Comprova sempre que el que llegeixes parla de Kea.

Kea es configura amb un fitxer JSON, i té un servei separat per a cada feina. A nosaltres només ens cal el d'IPv4: kea-dhcp4-server.

El fitxer de configuració, bloc a bloc

Tot viu a /etc/kea/kea-dhcp4.conf. Sembla llarg, però només hi ha quatre coses que hagis de tocar:

BlocQuè hi poses
interfaces-configPer quina targeta escolta el servidor
subnetLa xarxa que gestiona, amb màscara
poolsEl rang d'adreces que pot repartir
option-dataPorta d'enllaç, DNS i nom de domini

La resta (control-socket, lease-database) ve donada i no cal tocar-la: és on Kea guarda quines adreces té concedides.

Una configuració completa i mínima

Xarxa 192.168.1.0/24, servidor a la .1, repartint de la 100 a la 200:

{
"Dhcp4": {
  "interfaces-config": {
    "interfaces": [ "enp2s0" ]              // targeta personal1
  },
  "control-socket": {
    "socket-type": "unix",
    "socket-name": "/run/kea/kea4-ctrl-socket"
  },
  "lease-database": { "type": "memfile", "lfc-interval": 3600 },

  "valid-lifetime": 600,                    // durada de la concessió
  "max-valid-lifetime": 7200,

  "subnet4": [
    {
      "id": 1,
      "subnet": "192.168.1.0/24",
      "pools": [ { "pool": "192.168.1.100 - 192.168.1.200" } ],
      "option-data": [
        { "name": "routers",             "data": "192.168.1.1" },
        { "name": "domain-name-servers", "data": "9.9.9.9"     },
        { "name": "domain-name",         "data": "adria.internal" }
      ]
    }
  ]
}
}

Compte amb les comes i les claus. A JSON, cada element d'una llista en porta una menys l'últim. La que falta i la clau sense tancar deixen el servei sense arrencar, i és l'error número u: valida sempre el fitxer abans de reiniciar.

Reservar una IP per a un equip concret

Una reserva lliga una adreça MAC a una IP: aquell equip rebrà sempre la mateixa. S'escriu dins de la subxarxa, just després de option-data: 

      "reservations": [
        {
          "hw-address": "00:1a:2b:3c:4d:5e",
          "ip-address": "192.168.1.10"
        },
        {
          "hw-address": "00:1a:2b:3c:4d:5f",
          "ip-address": "192.168.1.11"
        }
      ]

L'adreça reservada ha d'estar dins de la subxarxa però fora del pool. Si la poses dins del rang, Kea la podria haver donat abans a un altre equip.

Muntar el servidor

Punt de partida: la targeta personal1 ja ha de tenir IP fixa (guia G1.1). Sense això, Kea no arrencarà.

  1. Instal·la el servei d'IPv4, que és l'únic que necessites:

    sudo apt update
sudo apt install -y kea-dhcp4-server

  2. Desa una còpia de la configuració original abans de tocar res:

    sudo cp /etc/kea/kea-dhcp4.conf /etc/kea/kea-dhcp4.conf.original

  3. Edita el fitxer i deixa'l com el de l'exemple, amb les teves dades:

    sudo nano /etc/kea/kea-dhcp4.conf

  4. Comprova la sintaxi abans d'arrencar. Kea té un mode de prova que llegeix el fitxer i et diu si està bé:

    sudo -u _kea kea-dhcp4 -t /etc/kea/kea-dhcp4.conf

    Va com l'usuari _kea, el del servei, i no com a root: l'AppArmor que porta el paquet no deixa que el programa obri fitxers fora dels seus. Si t'hi descuides, la resposta és Unable to open file encara que el fitxer hi sigui.

    Si falta una coma o una clau, aquí ho sabràs, amb el fitxer, la línia i la columna: syntax error, unexpected max-valid-lifetime, expecting "," or }. Si tot va bé, no diu res i acaba amb codi 0.

  5. Arrenca i comprova que està actiu:

    sudo systemctl restart kea-dhcp4-server
sudo systemctl status kea-dhcp4-server

    Ha de sortir active (running) en verd.

  6. Verifica que escolta al port 67:

    sudo ss -ulnp | grep :67

  7. Mira les concessions en directe mentre arrenques el client:

    sudo journalctl -u kea-dhcp4-server -f

    Veuràs línies DHCP4_LEASE_ALLOC amb la MAC i la IP concedida. La llista completa de concessions la tens a /var/lib/kea/kea-leases4.csv.

Ubuntu 26.04 El paquet porta Kea 3.0. Molta documentació i molts tutorials escriuen la validació com sudo kea-dhcp4 -t, sense l'usuari: així no funciona, perquè el perfil d'AppArmor del paquet no deixa que el programa obri el fitxer. Compara sempre amb la sortida de la teva màquina.

Comprovar que reparteix adreces

  1. El servei està actiu i escolta pel port UDP 67:

    systemctl status kea-dhcp4-server
ss -ulnp | grep :67

  2. Un client rep adreça. Amb el registre obert al servidor, engega el client i mira què hi passa:

    journalctl -u kea-dhcp4-server -f

    Hi han de sortir les quatre passes del DORA amb la MAC del client.

  3. La concessió ha quedat desada:

    cat /var/lib/kea/kea-leases4.csv

    Una línia amb la IP donada i la MAC de qui l'ha rebuda. Si hi ha reserva, la IP ha de ser la reservada.

Criteris professionals

  • Valida sempre abans d'arrencar amb sudo -u _kea kea-dhcp4 -t. Estalvia la meitat dels problemes.
  • Còpia de l'original. És la teva marxa enrere si t'hi perds.
  • Escolta només per la targeta interna. Mai posis la targeta que va a la xarxa del centre a interfaces.
  • Reserves fora del pool, i totes juntes en una zona d'adreces baixes.
  • Comenta la configuració amb //: Kea ho admet i el teu jo del mes vinent ho agrairà.

Errors habituals

El servei no arrenca

Causa Error de JSON (una coma sobrant) o la targeta de interfaces no existeix o no té IP.

Solució sudo -u _kea kea-dhcp4 -t /etc/kea/kea-dhcp4.conf et dona el motiu, la línia i la columna. Si el fitxer és correcte, mira journalctl -u kea-dhcp4-server -n 30.

El servei està actiu però el client no rep res

Causa Escolta per la targeta equivocada, o el client està en una xarxa diferent de la del subnet.

Solució Comprova amb ss -ulnp | grep :67 i, al servidor, sudo tcpdump -i enp2s0 -n port 67. Si no hi arriba el DISCOVER, el problema és de connexió, no de Kea.

La reserva no s'aplica

Causa La MAC està mal escrita, o el client encara té una concessió antiga vàlida.

Solució Copia la MAC de la sortida del client, no la transcriguis a mà. Al client, força la renovació amb sudo networkctl renew enp1s0.

El client rep IP però no té Internet

Causa Kea ha fet la seva feina. Falta que el servidor encamini el trànsit cap a fora.

Solució És el contingut de la guia G1.3: encaminament i NAT.

Resum

  • Kea substitueix isc-dhcp-server. La documentació antiga no serveix.
  • Es configura en JSON a /etc/kea/kea-dhcp4.conf.
  • Quatre blocs a tocar: interfaces-config, subnet, pools i option-data.
  • Les reserves van dins de la subxarxa i fora del pool.
  • Al comptar adreces d'un rang, els dos extrems hi entren.
