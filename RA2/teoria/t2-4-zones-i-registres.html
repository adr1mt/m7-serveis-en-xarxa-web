Zones i registres

Donar noms propis a la teva xarxa: zona directa, zona inversa i tipus de registre.

Què sabràs fer en acabar

  • Declarar una zona directa i una d'inversa a BIND.
  • Escriure un fitxer de zona amb el registre SOA ben posat.
  • Distingir els registres A, PTR, CNAME, MX, TXT i NS.
  • Recordar per què el punt final canvia el significat d'un nom.
  • Validar la zona i recarregar-la sense aturar el servei.

Dues zones per a la mateixa xarxa

Fins ara el teu servidor repetia el que deien els altres. Ara tindrà dades pròpies: serà autoritatiu d'una zona teva.

ZonaRespon aEs diu
Directa«Quina IP té aquest nom?»adria.internal
Inversa«Quin nom té aquesta IP?»1.168.192.in-addr.arpa

El nom de la zona inversa és la xarxa escrita al revés seguida de in-addr.arpa. Per a 192.168.1.0/24, els tres primers octets girats: 1.168.192. Fa estrany, però té sentit: així les adreces també es llegeixen de general a concret, com els noms.

Declarar les zones

Les zones es declaren a named.conf.local. Cada declaració diu tres coses: com es diu la zona, quin paper hi fa aquest servidor i on són les dades. 

zone "adria.internal" {
    type primary;
    file "/etc/bind/zones/db.adria.internal";
};

zone "1.168.192.in-addr.arpa" {
    type primary;
    file "/etc/bind/zones/db.192.168.1";
};

type primary vol dir que aquest servidor té l'original, escrit per tu. La documentació antiga en diu master: és el mateix, però el nom vigent és primary.

La capçalera de tota zona: el registre SOA

Tot fitxer de zona comença igual: el TTL per defecte i un registre SOA (Start Of Authority), que declara qui mana a la zona i cada quan s'ha de revisar.

CampQuè vol dir
SerialNúmero de versió. S'ha d'apujar a cada canvi
RefreshCada quant el secundari pregunta si hi ha novetats
RetryCada quant torna a provar si ha fallat
ExpireQuan el secundari deixa de servir dades velles
MinimumQuant es guarden les respostes negatives

El serial és el camp que més maldecaps dona: si no l'apuges, el secundari no s'assabenta de res. El format recomanat és AAAAMMDDNN.

Fitxer de zona directa

Per a adria.internal, amb el servidor a la 192.168.1.8:

$TTL 600
@   IN  SOA ns1.adria.internal. admin.adria.internal. (
            2026080101  ; Serial
            3600        ; Refresh
            1800        ; Retry
            604800      ; Expire
            600 )       ; Minimum

@       IN  NS      ns1.adria.internal.
ns1     IN  A       192.168.1.8
www     IN  A       192.168.1.8
portatil IN A       192.168.1.50
intranet IN CNAME   www.adria.internal.
@       IN  MX  10  correu.adria.internal.
correu  IN  A       192.168.1.9
@       IN  TXT     "Xarxa interna de proves"

La @ vol dir «la zona sencera», aquí adria.internal.. I el correu de l'administrador s'escriu amb un punt on aniria l'arrova: admin.adria.internal. és admin@adria.internal.

El punt final no és decoració

Un nom acabat en punt és absolut: es fa servir tal com és. Un nom sense punt és relatiu: BIND hi enganxa el nom de la zona al darrere.

Per això www dins de adria.internal vol dir www.adria.internal., però si escrius www.adria.internal sense punt, acabes amb www.adria.internal.adria.internal., que no existeix. És l'error més freqüent de tots.

Els tipus de registre que faràs servir

TipusPer a què
ANom → adreça IPv4
AAAANom → adreça IPv6
PTRAdreça → nom, a la zona inversa
CNAMEÀlies: un nom que apunta a un altre nom
MXQui rep el correu del domini, amb prioritat
NSQuins servidors tenen l'autoritat de la zona
TXTText lliure. S'usa per a verificacions i antispam

Dues regles: un CNAME apunta a un nom, mai a una IP, i el MX també ha d'apuntar a un nom que tingui el seu registre A.

Fitxer de zona inversa

Les mateixes màquines, al revés. Aquí el número de l'esquerra és l'últim octet:

$TTL 600
@   IN  SOA ns1.adria.internal. admin.adria.internal. (
            2026080101 3600 1800 604800 600 )

@       IN  NS      ns1.adria.internal.
8       IN  PTR     ns1.adria.internal.
9       IN  PTR     correu.adria.internal.
50      IN  PTR     portatil.adria.internal.

Els noms de la dreta van tots amb punt final: són d'una altra zona. I fixa't que www no hi surt: la inversa dona un nom per adreça, i el bo és el de la màquina, no el de l'àlies.

Crear i comprovar una zona

  1. Crea la carpeta de les teves zones:

    sudo mkdir -p /etc/bind/zones

  2. Declara les dues zones a named.conf.local i escriu els dos fitxers, seguint els exemples d'aquesta pàgina.

  3. Valida cada zona per separat. El primer argument és el nom de la zona i el segon el fitxer:

    sudo named-checkzone adria.internal \
     /etc/bind/zones/db.adria.internal

    Ha de dir OK i el número de serial. Fes el mateix amb la inversa.

  4. Valida la configuració i recarrega sense aturar el servei:

    sudo named-checkconf
sudo rndc reload

  5. Comprova-ho amb dig, preguntant al teu servidor:

    dig @192.168.1.8 www.adria.internal +short
dig @192.168.1.8 adria.internal MX +short
dig @192.168.1.8 -x 192.168.1.8 +short

    La resposta ha de portar la marca aa: ets tu qui té l'autoritat.

Criteris professionals

  • Apuja el serial a cada canvi. Amb format de data, i sense excepcions.
  • named-checkzone abans de recarregar: una zona amb un error no es carrega i el servei es queda amb la versió antiga.
  • Punt final a tots els noms absoluts. Repassa'ls un a un.
  • Cada màquina, un A i el seu PTR. Molts serveis comproven la inversa.
  • Àlies amb CNAME, no repetint el registre A: si canvia la IP, només toques un lloc.

Errors habituals

named-checkzone es queixa de NS record o de l'SOA

Causa Falta el registre NS de la zona, o el nom del SOA no té punt final.

Solució Compara la capçalera amb l'exemple, caràcter a caràcter.

El nom es resol amb el domini repetit dues vegades

Causa Has escrit un nom absolut sense punt final.

Solució dig @elteuservidor nom i mira la resposta sencera: hi veuràs el nom duplicat.

Has editat la zona i el canvi no es veu

Causa No has apujat el serial, o no has recarregat, o el client té la resposta a la memòria cau.

Solució Serial, rndc reload i pregunta amb dig @servidor, que se salta la cau del client.

Resum

  • Cada xarxa vol dues zones: la directa i la inversa in-addr.arpa.
  • Les zones es declaren a named.conf.local amb type primary.
  • Tot fitxer de zona comença amb $TTL i un SOA; el serial s'apuja sempre.
  • A i PTR per a les màquines, CNAME per als àlies, MX per al correu, NS per als servidors.
  • El punt final distingeix un nom absolut d'un de relatiu.
