Transferència de fitxers i FTP

Per què FTP fa servir dues connexions, i què canvia entre el mode actiu i el passiu.

Què sabràs fer en acabar

  • Explicar per a què serveix un servei de transferència de fitxers i quan se'n fa servir un altre.
  • Distingir el canal de control del canal de dades.
  • Diferenciar el mode actiu del mode passiu i saber quin funciona darrere d'un NAT.
  • Llegir els codis numèrics que respon un servidor FTP.
  • Fer una sessió completa amb un client de línia d'ordres.

Un servei per moure fitxers, no per compartir-los

Un servei de transferència de fitxers serveix perquè una màquina pugi o baixi fitxers d'un servidor, amb un compte i uns permisos. No és el mateix que una carpeta compartida: aquí el fitxer viatja sencer i es queda a les dues bandes.

Encara avui és la manera habitual de fer tres feines:

  • Publicar fitxers perquè qualsevol se'ls baixi, sense donar-los cap compte.
  • Recollir feina de gent de fora, cadascú al seu directori.
  • Deixar còpies de seguretat en una màquina que no és la que les genera.

Dos canals: control i dades

FTP (File Transfer Protocol) és de 1971 i té una particularitat que cap protocol modern repeteix: fa servir dues connexions TCP alhora.

CanalPortQuè hi passa
Control21Ordres i respostes. Dura tota la sessió
DadesvariableEl contingut dels fitxers i els llistats. S'obre i es tanca a cada transferència

Aquesta separació és la font de gairebé tots els problemes d'FTP: el tallafocs veu passar la connexió del port 21 i la deixa, però la de dades va per un port que ningú no ha previst.

Mode actiu i mode passiu

La pregunta que resolen aquests dos modes és sempre la mateixa: qui obre la connexió de dades, el client o el servidor.

En actiu el servidor truca a la porta del client, i el router del client no sap a qui l'ha de passar. Per això tots els clients d'avui arrenquen en passiu.

Una sessió vista per dins

El client tradueix el que escrius a ordres del protocol. Aquestes són les que envia per baixar un fitxer, amb la resposta del servidor al davant: 

220 (vsFTPd 3.0.5)          # el servidor es presenta
USER alumne
331 Please specify the password.
PASS ······
230 Login successful.
EPSV
229 Entering Extended Passive Mode (|||34277|)
RETR informe.pdf
150 Opening BINARY mode data connection
226 Transfer complete.

El número entre barres del 229 és el port on has d'anar a buscar les dades: el 34277. L'adreça no cal, perquè ja és la del servidor amb qui parles.

El client d'avui demana EPSV, la versió que també val per a IPv6. Si en trobes un de vell, demanarà PASV i el servidor li respondrà amb sis números, 227 Entering Passive Mode (192,168,1,8,201,44): els quatre primers són la IP i els dos últims el port, 201×256 + 44 = 51500.

Els codis numèrics es llegeixen per la primera xifra

No cal memoritzar-los. La primera xifra ja diu de què va la resposta, i això et serveix per a qualsevol servidor FTP del món.

Comença perVol dirExemple
2Fet correctament230 Login successful
3Falta un pas més331 Specify the password
4Error temporal, torna-ho a provar421 Timeout
5Error definitiu530 Login incorrect

Mode text i mode binari

FTP pot transferir de dues maneres. En mode text (ASCII) converteix el final de línia al del sistema de destinació; en mode binari copia byte a byte sense tocar res.

Existeix perquè Windows acaba les línies amb CR LF i Linux només amb LF. Passar una imatge o un PDF en mode text el corromp: el fitxer arriba amb bytes canviats i no s'obre.

Avui tots els clients arrenquen en binari i no s'hi toca. Ho has de conèixer perquè encara apareix a la documentació i als exàmens, i perquè explica avaries antigues molt cèlebres.

La contrasenya viatja escrita

FTP és anterior al xifratge. L'ordre PASS envia la contrasenya tal com és, en text pla, i el mateix passa amb el contingut dels fitxers.

Qualsevol que comparteixi xarxa amb el client —una wifi d'hotel, un cable a l'aula— pot llegir l'usuari i la contrasenya amb un capturador de trànsit i sense cap coneixement especial. A la T3.3 ho veuràs tu mateix amb tcpdump.

Per això FTP en clar ja no es desplega mai cap a Internet. Sobreviu en xarxes internes i tancades, i quan cal exposar-lo es fa amb FTPS o es canvia per SFTP.

La teva primera sessió FTP

Instal·la el servidor amb els valors de sèrie i mira el protocol funcionant.

  1. Instal·la el servidor i un client de text:

    sudo apt update
sudo apt install -y vsftpd ftp

  2. Comprova que escolta al port 21:

    systemctl status vsftpd
sudo ss -lntp | grep :21

  3. Deixa un fitxer de prova a la teva carpeta:

    echo "hola" > ~/prova.txt

  4. Connecta't i mira els codis que van sortint:

    ftp localhost

    Dins: ls, get prova.txt i bye.

  5. Prova de pujar-ne un, que ha de fallar:

    put prova.txt copia.txt
550 Permission denied.

    No és cap avaria: de sèrie no es pot escriure. Es canvia a la G3.1.

  6. Mira en quin mode estàs: l'ordre passive canvia d'un mode a l'altre.

    passive
Passive mode: off; fallback to active mode: off.

    Repeteix el ls amb cada mode: surt 229 Entering Extended Passive Mode o 200 EPRT command successful.

Ubuntu 26.04 El client de text es diu tnftp; apt install ftp continua funcionant perquè és un paquet pont. Arrenca en mode passiu.

Criteris professionals

  • Passiu per defecte: és l'únic que funciona des de darrere d'un router.
  • Rang de ports de dades acotat amb pasv_min_port i pasv_max_port, perquè el tallafocs el pugui obrir.
  • Mai FTP en clar cap a Internet: dins de la xarxa interna i prou.
  • Llegeix el codi de resposta abans de tocar res: ja et diu de qui és el problema.
  • Un servei per a una feina: si només vols publicar fitxers per baixar, un servidor web ho fa millor.

Errors habituals

Connecta i autentica, però ls es queda penjat

Causa El canal de control va bé i el de dades no: estàs en mode actiu darrere d'un NAT o d'un tallafocs.

Solució Posa el client en passiu amb l'ordre passive.

530 Login incorrect amb la contrasenya bona

Causa L'usuari té prohibit l'accés: root i els comptes de sistema són a /etc/ftpusers.

Solució Fes servir un usuari normal. No treguis root d'aquesta llista.

El fitxer baixat no s'obre

Causa S'ha transferit en mode text i s'han canviat els finals de línia.

Solució Escriu binary dins de la sessió i torna a baixar-lo.

ftp: command not found

Causa Ubuntu Server no porta cap client FTP instal·lat.

Solució sudo apt install ftp, o fes servir lftp, més complet.

Resum

  • FTP fa servir dos canals: control al port 21 i dades a part.
  • En actiu connecta el servidor; en passiu, el client. Avui, passiu.
  • La primera xifra del codi de resposta ja et diu si ha anat bé, falta un pas o hi ha error.
  • El mode binari és l'únic segur; el mode text només retoca finals de línia.
  • Tot viatja en clar, contrasenya inclosa.
