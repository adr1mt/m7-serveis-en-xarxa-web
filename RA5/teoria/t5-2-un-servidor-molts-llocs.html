Un servidor, molts llocs

Una sola màquina, molts webs: el servidor tria pel nom, no per la IP.

Què sabràs fer en acabar

  • Explicar per què un sol servidor pot allotjar molts llocs web.
  • Descriure el paper de la capçalera Host en la petició.
  • Dir què respon el servidor quan cap nom coincideix.
  • Explicar qui resol el nom d'un lloc: el fitxer hosts o una zona DNS.

Molts llocs, una sola IP

Una màquina pot tenir una sola adreça IP i servir desenes de llocs web diferents. El servidor ho fa possible mirant, a cada petició, quin nom ha demanat el navegador: no calen IP diferents per a cada lloc.

Aquest repartiment també es pot fer per IP diferent per lloc, o per port diferent, però és poc pràctic: cada IP s'ha de gestionar i cada port s'ha de recordar. Per nom és el que fan servir gairebé tots els servidors web.

La capçalera Host

Cada petició HTTP porta una capçalera Host amb el nom que l'usuari ha escrit al navegador. El servidor la llig i decideix quin lloc respon, encara que totes les peticions arribin a la mateixa IP i el mateix port.

El navegador demanaCapçalera Host
http://web1.internal/Host: web1.internal
http://web2.internal/Host: web2.internal

El lloc per defecte

Quan cap lloc configurat coincideix amb el nom demanat, el servidor respon amb el lloc per defecte. És el que es veu si s'entra per la IP directament: la IP no és cap nom, així que no coincideix amb res i respon el lloc per defecte, no el que esperaves.

Entrar per IP no és entrar pel nom

Un usuari escriu la IP del servidor al navegador esperant veure botiga.internal, però rep el lloc per defecte: el navegador no ha enviat cap capçalera Host amb el nom del lloc, només l'adreça.

Qui resol el nom

Al laboratori, el fitxer hosts del client fa d'atzucac ràpid per apuntar un nom a una IP sense DNS. En producció, el que funciona és publicar el nom en una zona DNS pròpia —com la que vas muntar a RA2— perquè qualsevol client el resolgui sense tocar-lo a mà.

Canviar de lloc sense canviar d'IP

Es pot forçar la capçalera Host amb curl i veure com respon un lloc o un altre contra la mateixa IP: 

curl -H "Host: web1.internal" http://203.0.113.10/
<h1>Lloc 1</h1>

curl -H "Host: web2.internal" http://203.0.113.10/
<h1>Lloc 2</h1>

Criteris professionals

  • Publica el nom en una zona DNS pròpia; el fitxer hosts és només per a proves.
  • Configura sempre un lloc per defecte pensat, no el primer que quedi per casualitat.
  • No dónes per fet que entrar per IP mostra el lloc esperat.

Errors habituals

Entrar per IP i no veure el lloc esperat

Causa La IP no porta cap nom, i el servidor respon amb el lloc per defecte.

Solució Entra pel nom del lloc, resolt per hosts o per una zona DNS.

Pensar que cada lloc necessita la seva pròpia IP

Causa Es confon repartiment per nom amb repartiment per IP.

Solució Amb un sol IP n'hi ha prou: el servidor tria pel nom que arriba a la capçalera Host.

Resum

  • Un servidor tria el lloc pel nom de la capçalera Host, no per la IP.
  • Sense coincidència, respon el lloc per defecte.
  • El repartiment per IP o per port existeix, però per nom és el normal.
  • El nom el resol el hosts del client al laboratori, i una zona DNS en producció (RA2).
