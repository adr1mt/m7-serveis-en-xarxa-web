Qui pot entrar al web

Qui ets i què pots veure són dues preguntes diferents.

Què sabràs fer en acabar

  • Distingir autenticació d'autorització.
  • Explicar com funciona l'autenticació bàsica HTTP i per què necessita HTTPS.
  • Valorar la restricció per adreça d'origen i les seves limitacions.
  • Explicar per a què serveixen els grups d'usuaris.

Autenticació i autorització

Autenticació respon «qui ets»: el servidor demana una credencial i la comprova. Autorització respon «què pots veure», un cop ja se sap qui ets. Un servidor pot autenticar sense autoritzar res més enllà de l'accés bàsic, o autoritzar de manera diferent segons el grup de qui ja s'ha autenticat.

PreguntaResultat
AutenticacióQui ets?Usuari i contrasenya vàlids o no
AutoritzacióQuè pots veure?Accés a un recurs concret o no

Autenticació bàsica HTTP

Quan un client demana un recurs protegit, el servidor respon 401 i el navegador mostra un diàleg d'usuari i contrasenya. Les credencials viatgen codificades en base64, no xifrades: sense HTTPS és exactament com enviar-les en text pla, ja que codificar-les no és el mateix que protegir-les.

Restricció per adreça d'origen

Un servidor pot permetre o denegar l'accés segons la IP d'origen de la petició. És útil per limitar un recurs a una xarxa interna, però és una protecció feble: una IP identifica una màquina, no una persona, i qualsevol que hi tingui accés físic o de xarxa passa igual el filtre.

Grups d'usuaris

Quan diverses zones protegides han d'admetre el mateix conjunt de persones, es defineixen grups: es dóna accés al grup, no a cada usuari repetit a cada zona. Afegir o treure algú es fa un sol cop, al grup, i tots els recursos que l'usen queden actualitzats.

Protegir una carpeta no protegeix la resta

Restringir l'accés a una carpeta concreta del lloc no fa que la resta del web quedi protegit: cada zona necessita la seva pròpia regla d'autenticació o autorització. Un directori sense regla pròpia és tan accessible com abans.

Zona d'administració combinada

Un panell d'administració intern sol combinar les dues coses: autenticació bàsica per saber qui hi entra i restricció per adreça perquè, encara que algú robi una contrasenya, només la pugui fer servir des de la xarxa interna.

Veure el 401 i la capçalera d'autenticació

curl -I contra una zona protegida mostra el codi 401 i la capçalera que indica quin tipus d'autenticació espera el servidor: 

curl -I http://web.internal/privat/
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Basic realm="Zona restringida"

Criteris professionals

  • Autenticació bàsica, sempre amb HTTPS per davant.
  • Restricció per IP com a capa extra, mai com a única protecció.
  • Usa grups quan diverses zones comparteixin el mateix accés.

Errors habituals

Confiar només en la restricció per IP

Causa Sembla que una IP identifica a una persona concreta.

Solució Una IP identifica una màquina o una xarxa, no un usuari. Combina-la amb autenticació si cal saber qui hi entra.

Pensar que l'autenticació bàsica xifra les credencials

Causa Es confon codificar amb xifrar.

Solució Sense HTTPS, l'usuari i la contrasenya viatgen com si anessin en text pla.

Donar per protegit tot el lloc perquè una carpeta ho està

Causa Es dona per fet que la regla s'aplica a tot el servidor.

Solució Cada zona necessita la seva pròpia regla d'accés.

Resum

  • Autenticació: qui ets. Autorització: què pots veure.
  • Autenticació bàsica: 401 i credencials codificades, no xifrades. Cal HTTPS.
  • Restricció per IP: útil, però feble com a única protecció.
  • Grups evita repetir la llista d'usuaris a cada zona.
  • Protegir una carpeta no protegeix la resta del lloc.
