Client i servidor

Un servei web escolta peticions i en respon amb contingut. El navegador (client) envia la petició, l'interpreta i la mostra; el servidor la rep, busca el recurs al disc i l'envia. Cap dels dos fa la feina de l'altre: el servidor no sap com es veurà la pàgina, i el navegador no guarda el contingut original.

ClientServidor
FaEnvia la petició, interpreta l'HTMLRep, busca i respon
ProgramaNavegadorApache, Nginx…

Petició i resposta

HTTP defineix com es demana i com es respon. El client demana un recurs amb un mètode —gairebé sempre GET— i el servidor respon amb un codi d'estat i el contingut.

CodiSignificat
200OK, aquí tens el recurs
301El recurs s'ha mogut permanentment
403Prohibit: no tens permís
404No existeix cap recurs amb eixe nom
500Error intern del servidor

Una pàgina web no és un sol recurs: el navegador en demana un per cada imatge, full d'estils i script que hi trobi, cadascun amb la seva pròpia petició i resposta.

Ports i contingut estàtic

Els servidors web escolten al port 80 per HTTP i al 443 per HTTPS. Per al contingut estàtic —el que no canvia segons qui el demani—, el servidor simplement retorna un fitxer del disc. Si la URL no en diu cap, el servidor carrega index.html per defecte.

El servidor corre com un usuari del sistema sense privilegis, no com a root: només pot llegir el que els permisos li deixen. Per això els directoris van amb permís 755 i els fitxers amb 644: lectura per a tothom, escriptura només per al propietari. Un 777 no arregla res, obre el fitxer a qualsevol que hi arribi.

Una pàgina, moltes peticions

Una pàgina amb una imatge i un full d'estils genera com a mínim tres peticions: una per l'HTML, una per la imatge i una pel CSS. Si l'HTML respon 200 però la imatge no existeix al disc, eixa petició concreta torna 404 mentre la resta de la pàgina es mostra igual.

Quan el servei no respon

Si el servei web no està instal·lat, està aturat o mal configurat, el client no rep resposta i el navegador mostra un error de connexió, no un codi HTTP: el codi d'estat només existeix si el servidor ha arribat a respondre.

Mirar una resposta HTTP crua

curl -I demana només les capçaleres, sense el cos de la pàgina: es veu la línia d'estat i què diu el servidor sobre el que envia. 

curl -I http://exemple.internal/
HTTP/1.1 200 OK
Server: nginx/1.24.0
Content-Type: text/html
Content-Length: 612

Criteris professionals

  • 755 / 644, mai 777: el mínim permís que fa falta.
  • El propietari dels fitxers no ha de ser l'usuari del servidor web.
  • Un 404 en un recurs no vol dir que tota la pàgina falli.

Errors habituals

Donar permisos 777 per "arreglar-ho ràpid"

Causa Un 403 fa pensar que falta permís d'escriptura.

Solució El servidor només necessita lectura. Revisa propietari i permisos 755/644 abans de tocar res més.

Confondre «no arriba resposta» amb un codi d'estat

Causa El navegador mostra un error genèric quan no hi ha servei.

Solució Un 404 o un 500 són respostes del servidor; un error de connexió vol dir que ni ha arribat a respondre.

Resum

  • El client demana amb GET, el servidor respon amb un codi d'estat i contingut.
  • Ports 80 (HTTP) i 443 (HTTPS).
  • Contingut estàtic: fitxers del disc; index.html per defecte.
  • El servidor corre sense privilegis: permisos 755/644, mai 777.
  • Següent: T5.2, com un mateix servidor serveix diversos llocs.
