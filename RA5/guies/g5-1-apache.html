Guia: Apache HTTP Server

Manual de configuració d'Apache, de la instal·lació al proxy invers.

Què hi ha en aquesta guia

Documentació oficial: httpd.apache.org/docs/2.4/es

  • Punt de partida: Ubuntu Server 26.04 acabat d'instal·lar, amb la targeta puigcastellar1.
  • Dos noms d'exemple: web1.internal i web2.internal.
  • Cobreix hosts virtuals, HTTPS, control d'accés, mòduls i proxy invers. Per fer el mateix lloc amb un altre servidor, G5.2.

Estructura de /etc/apache2

Apache guarda cada tipus de configuració en un parell de directoris: un de -available amb totes les opcions que existeixen i un de -enabled amb enllaços simbòlics només a les actives. apache2.conf és el fitxer principal i inclou la resta; ports.conf diu en quins ports escolta (80 i 443 per defecte).

DirectoriConté
mods-available / mods-enabled Mòduls instal·lats i actius
sites-available / sites-enabled Hosts virtuals declarats i actius
conf-available / conf-enabled Fragments de configuració global
OrdreFa
a2enmod / a2dismod Activa o desactiva un mòdul
a2ensite / a2dissite Activa o desactiva un lloc
a2enconf / a2disconf Activa o desactiva un fragment de configuració

Els registres viuen a /var/log/apache2: access.log és el del lloc per defecte, other_vhosts_access.log el de la resta d'hosts virtuals i error.log els errors de tots.

Instal·lar Apache i fer la primera comprovació

  1. Instal·la el paquet:

    sudo apt update
sudo apt install apache2

    S'inicia sol i queda actiu al port 80 de totes les targetes, amb el lloc 000-default.conf ja habilitat.

  2. Comprova el servei:

    systemctl status apache2

    Ha de sortir active (running).

  3. Des del client, esbrina la IP del servidor a puigcastellar1:

    ip -brief a

    I obre http://IP-DEL-SERVIDOR al navegador: ha de sortir la pàgina «Apache2 Default Page».

Publicar contingut propi

  1. Crea el directori del lloc, fora del DocumentRoot per defecte:

    sudo mkdir -p /var/www/web1.internal/public_html

  2. Escriu una pàgina de prova a dins, per exemple index.html amb un missatge identificatiu.

  3. Ajusta propietari i permisos: propietari l'administrador i grup www-data, directoris 755 i fitxers 644. Mai 777.

    sudo chown -R adr1:www-data \
  /var/www/web1.internal
sudo find /var/www/web1.internal \
  -type d -exec chmod 755 {} \;
sudo find /var/www/web1.internal \
  -type f -exec chmod 644 {} \;

Publicar-lo amb un host virtual per nom

  1. Crea el fitxer del lloc:

    sudo nano /etc/apache2/sites-available/web1.internal.conf
    <VirtualHost *:80>
    ServerName web1.internal
    ServerAlias www.web1.internal
    DocumentRoot /var/www/web1.internal/public_html
</VirtualHost>

  2. Activa el lloc i comprova la sintaxi abans de recarregar (mai recarreguis a cegues):

    sudo a2ensite web1.internal.conf
sudo apache2ctl -t
sudo systemctl reload apache2

  3. Al client, afegeix el nom a /etc/hosts amb la IP del servidor:

    IP-DEL-SERVIDOR web1.internal

    I obre http://web1.internal.

Directives dins <VirtualHost>

Dins d'un bloc <VirtualHost> es redefineixen només els valors que han de canviar respecte a la configuració global. El primer lloc que es carrega —per ordre alfabètic dels fitxers— es converteix en el lloc per defecte i respon a qualsevol petició que no coincideixi amb cap ServerName.

DirectivaFa
ServerName Nom pel qual respon aquest lloc
ServerAlias Noms addicionals que també serveix
DocumentRoot Directori amb els fitxers del lloc
SSLEngine Activa TLS en aquest bloc
SSLCertificateFile Ruta del certificat
SSLCertificateKeyFile Ruta de la clau privada
Redirect permanent Envia el trànsit a una altra URL

HTTPS amb certificat autofirmat

  1. Activa el mòdul SSL:

    sudo a2enmod ssl

  2. Prepara un fitxer de configuració amb els dos noms al subjectAltName (SAN): els navegadors comproven el SAN, no el Common Name.

    sudo mkdir /etc/apache2/ssl
sudo nano /etc/apache2/ssl/openssl.cnf
    [req]
distinguished_name = req_distinguished_name
x509_extensions = v3_req
prompt = no
[req_distinguished_name]
CN = web1.internal
[v3_req]
keyUsage = keyEncipherment, dataEncipherment
extendedKeyUsage = serverAuth
subjectAltName = @alt_names
[alt_names]
DNS.1 = web1.internal
DNS.2 = web2.internal
    Compte Ha de dir x509_extensions. Amb req_extensions, que és el que posen molts manuals, el certificat surt sense SAN i el navegador el rebutja pel nom encara que el Common Name sigui correcte.

  3. Genera la clau i el certificat a partir d'aquest fitxer:

    sudo openssl req -x509 -nodes -days 365 \
  -newkey rsa:2048 \
  -keyout /etc/apache2/ssl/apache.key \
  -out /etc/apache2/ssl/apache.crt \
  -config /etc/apache2/ssl/openssl.cnf

  4. Afegeix el bloc de port 443 al mateix fitxer del lloc:

    <VirtualHost *:443>
    ServerName web1.internal
    ServerAlias www.web1.internal
    DocumentRoot /var/www/web1.internal/public_html
    SSLEngine on
    SSLCertificateFile /etc/apache2/ssl/apache.crt
    SSLCertificateKeyFile /etc/apache2/ssl/apache.key
</VirtualHost>

  5. Redirigeix el 80 al 443, dins del bloc de port 80 del mateix fitxer:

    <VirtualHost *:80>
    ServerName web1.internal
    ServerAlias www.web1.internal
    Redirect permanent / https://web1.internal/
</VirtualHost>
    sudo apache2ctl -t
sudo systemctl reload apache2

Control d'accés

  1. Crea el fitxer de contrasenyes, sempre fora del DocumentRoot:

    sudo htpasswd -c /etc/apache2/.htpasswd admin
sudo htpasswd /etc/apache2/.htpasswd visitant

    -c només al primer usuari: crea el fitxer i l'esborraria si tornessis a fer-lo servir.

  2. Crea el fitxer de grups:

    sudo nano /etc/apache2/.htgroup
    administradors: admin
convidats: visitant

  3. Afegeix els tres casos dins el bloc <VirtualHost *:443>, cadascun sobre un <Directory> propi:

    <Directory /var/www/web1.internal/public_html/privat>
    AuthType Basic
    AuthName "Zona restringida"
    AuthUserFile /etc/apache2/.htpasswd
    Require valid-user
</Directory>

<Directory /var/www/web1.internal/public_html/bloqueig>
    <RequireAll>
        Require all granted
        Require not ip 192.168.1.50
    </RequireAll>
</Directory>

<Directory /var/www/web1.internal/public_html/admins>
    AuthType Basic
    AuthName "Només administradors"
    AuthUserFile /etc/apache2/.htpasswd
    AuthGroupFile /etc/apache2/.htgroup
    Require group administradors
</Directory>

  4. Activa el mòdul de grups —no és actiu de sèrie— i recarrega:

    sudo a2enmod authz_groupfile
sudo apache2ctl -t
sudo systemctl reload apache2

Estat del servidor i PHP

  1. mod_status sol venir actiu de sèrie, restringit a l'ordinador local. Comprova-ho i, si cal, edita /etc/apache2/mods-available/status.conf perquè el <Location "/server-status"> tingui Require ip 127.0.0.1:

    apache2ctl -M | grep status
sudo systemctl reload apache2

    Visita /server-status des del servidor mateix.

  2. PHP: instal·la el mòdul i escriu una pàgina de prova.

    sudo apt install libapache2-mod-php
echo "<?php phpinfo(); ?>" | sudo tee \
  /var/www/web1.internal/public_html/info.php

Proxy invers cap a un servidor intern

Aquest lloc no serveix fitxers propis: reenvia cada petició a un servidor de la xarxa interna i en retorna la resposta.

  1. Activa els mòduls de proxy:

    sudo a2enmod proxy proxy_http

  2. Crea el lloc, sense DocumentRoot:

    sudo nano /etc/apache2/sites-available/proxy.internal.conf
    <VirtualHost *:80>
    ServerName proxy.internal
    ProxyPreserveHost On
    ProxyPass / http://IP-SERVIDOR-INTERN/
    ProxyPassReverse / http://IP-SERVIDOR-INTERN/
</VirtualHost>

  3. Activa i comprova:

    sudo a2ensite proxy.internal.conf
sudo apache2ctl -t
sudo systemctl reload apache2

    IP-SERVIDOR-INTERN és la IP del servidor de darrere, esbrinada amb ip -brief a en aquella màquina. ProxyPreserveHost manté la capçalera Host original en comptes de substituir-la per la del servidor intern.

Comprovació de conjunt, des del client

  1. http://web1.internal i http://web2.internal responen cadascun amb el seu contingut, i redirigeixen a https://.

  2. Entrar a la carpeta protegida demana usuari i contrasenya, i el navegador avisa que el certificat és autofirmat.

  3. Al servidor, apache2ctl -M llista els mòduls actius: hi han de sortir ssl, authz_groupfile i, si s'ha fet el pas 10, proxy i proxy_http.

    apache2ctl -M | grep -E "ssl|proxy|groupfile"

Criteris professionals

  • Mai 777: directoris 755, fitxers 644.
  • El fitxer de contrasenyes, sempre fora del DocumentRoot.
  • apache2ctl -t abans de qualsevol reload.
  • Desactiva 000-default quan el servidor és d'un sol lloc concret.
  • Activa només els mòduls que facis servir.
  • El certificat autofirmat és per a laboratori; en producció, un de signat per una autoritat reconeguda.

Errors habituals

Entro per la IP i surt un lloc que no és el que esperava

Causa Sense capçalera Host coneguda, respon el primer lloc carregat: el per defecte.

Solució Desactiva 000-default amb a2dissite o entra pel nom, no per la IP.

Actives el lloc amb a2ensite i no canvia res

Causa a2ensite només crea l'enllaç a sites-enabled; Apache no rellegeix la configuració sol.

Solució sudo systemctl reload apache2.

El navegador avisa que la connexió no és privada

Causa El certificat és autofirmat: cap navegador el reconeix, però la comunicació sí que va xifrada.

Solució Accepta l'excepció en un laboratori; en producció cal un certificat signat.

Apache respon 403 Forbidden

Causa Permisos del DocumentRoot massa restrictius o propietari equivocat.

Solució Comprova que els directoris són 755 i el grup és www-data.

El nom no resol al client

Causa Falta la línia a /etc/hosts del client, o té la IP equivocada.

Solució Afegeix-la amb la IP que doni ip -brief a al servidor.

Apache no arrenca després d'editar un fitxer

Causa Error de sintaxi al fitxer que s'acaba de tocar.

Solució apache2ctl -t abans de recarregar sempre indica la línia amb el problema.
