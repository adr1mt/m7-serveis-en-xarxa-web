Guia: Nginx

Manual de configuració de Nginx, dels blocs de servidor a HTTPS.

Què hi ha en aquesta guia

Documentació oficial: nginx.org/en/docs

  • Punt de partida: Ubuntu Server 26.04 acabat d'instal·lar, amb la targeta puigcastellar1.
  • Nom d'exemple: web1.internal.
  • Cobreix el bloc server, la pàgina d'error, capçaleres de seguretat i HTTPS.
Ubuntu 26.04 Apache i Nginx no poden escoltar tots dos al port 80 de la mateixa màquina. Si véns de G5.1, para Apache (sudo systemctl stop apache2) o fes servir una màquina nova.

Estructura de /etc/nginx

nginx.conf és el fitxer principal i inclou la resta. Els llocs es declaren a sites-available i s'activen amb un enllaç simbòlic manual a sites-enabled: Nginx no té cap ordre equivalent a a2ensite.

DirectivaDins d'un bloc server, fa
listenPort i protocol en què escolta
server_nameNom pel qual respon aquest bloc
rootDirectori amb els fitxers del lloc
indexFitxers que compten com a índex
locationConfiguració per a una ruta concreta
try_filesOrdre de fitxers a provar abans de fallar
access_log / error_logRuta dels registres d'aquest lloc
autoindexLlistar el directori si no hi ha índex

Instal·lar Nginx i preparar el contingut

  1. Instal·la el paquet:

    sudo apt update
sudo apt install nginx

  2. Desactiva el lloc per defecte, esborrant l'enllaç (Nginx no té a2dissite):

    sudo unlink /etc/nginx/sites-enabled/default

  3. Crea el directori del lloc i una pàgina de prova:

    sudo mkdir -p /var/www/web1.internal/html

  4. Ajusta propietari i permisos: propietari i grup www-data, directoris 755 i fitxers 644. Mai 777.

    sudo chown -R www-data:www-data \
  /var/www/web1.internal
sudo chmod -R 755 /var/www/web1.internal

El bloc server i l'enllaç simbòlic

  1. Crea el fitxer del lloc:

    sudo nano /etc/nginx/sites-available/web1.internal
    server {
    listen 80;
    listen [::]:80;

    server_name web1.internal;
    root /var/www/web1.internal/html;
    index index.html;

    access_log /var/log/nginx/web1_access.log;
    error_log /var/log/nginx/web1_error.log;

    location / {
        try_files $uri $uri/ =404;
    }

    autoindex off;
}

  2. Enllaça'l a sites-enabled, comprova la sintaxi i recarrega:

    sudo ln -s /etc/nginx/sites-available/web1.internal \
  /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

  3. Al client, esbrina la IP amb ip -brief a al servidor i afegeix el nom a /etc/hosts:

    IP-DEL-SERVIDOR web1.internal

    I obre http://web1.internal.

Pàgina d'error 404 personalitzada

  1. Escriu la pàgina dins del mateix root:

    sudo nano /var/www/web1.internal/\
html/error404.html

  2. Afegeix la directiva dins del bloc server:

    error_page 404 /error404.html;
    sudo nginx -t
sudo systemctl reload nginx

    Prova amb una URL que no existeixi.

Capçaleres de seguretat

  1. Afegeix-les dins del bloc server:

    add_header X-Frame-Options "SAMEORIGIN";
add_header X-Content-Type-Options "nosniff";

  2. Comprova i recarrega:

    sudo nginx -t
sudo systemctl reload nginx

HTTPS amb certificat autofirmat

  1. Genera la clau i el certificat. El Common Name ha de coincidir amb el nom del lloc:

    sudo mkdir /etc/nginx/ssl
sudo openssl req -x509 -nodes -days 365 \
  -newkey rsa:2048 \
  -keyout /etc/nginx/ssl/web1.key \
  -out /etc/nginx/ssl/web1.crt

  2. Reescriu el fitxer del lloc amb un bloc per al 443 i un altre pel 80 que redirigeix:

    server {
    listen 443 ssl;
    listen [::]:443 ssl;

    server_name web1.internal;
    root /var/www/web1.internal/html;
    index index.html;

    ssl_certificate /etc/nginx/ssl/web1.crt;
    ssl_certificate_key /etc/nginx/ssl/web1.key;

    location / {
        try_files $uri $uri/ =404;
    }
}

server {
    listen 80;
    listen [::]:80;

    server_name web1.internal;
    return 301 https://$host$request_uri;
}

  3. Comprova i recarrega:

    sudo nginx -t
sudo systemctl reload nginx

  4. Des del client, obre https://web1.internal. El navegador avisa que el certificat és autofirmat: accepta l'excepció per continuar.

Comprovació de conjunt, des del client

  1. http://web1.internal redirigeix a https://web1.internal, i el lloc respon amb el contingut esperat.

  2. Una URL inexistent mostra la pàgina d'error personalitzada, no la genèrica de Nginx.

  3. Al servidor, les capçaleres de resposta inclouen X-Frame-Options i X-Content-Type-Options, i els registres d'aquest lloc creixen a /var/log/nginx.

Criteris professionals

  • Mai 777: directoris 755, fitxers 644.
  • Desactiva sempre el lloc per defecte quan el servidor és d'un sol lloc concret.
  • nginx -t abans de qualsevol reload.
  • Un server_name per lloc, mai el mateix nom en dos fitxers actius alhora.
  • El certificat autofirmat és per a laboratori; en producció, un de signat per una autoritat reconeguda.

Errors habituals

Nginx no arrenca després d'instal·lar-lo

Causa Ja hi ha un altre servei —sovint Apache— escoltant al port 80 de la mateixa màquina.

Solució Para l'altre servei (sudo systemctl stop apache2) o usa una màquina nova.

He enllaçat el lloc i segueix sortint el per defecte

Causa L'enllaç de sites-enabled/default encara hi és.

Solució sudo unlink /etc/nginx/sites-enabled/default i recarrega.

nginx -t diu que hi ha un error de sintaxi

Causa Falta un punt i coma o una clau al fitxer que s'acaba de tocar.

Solució El missatge indica el fitxer i la línia exactes: corregeix-la abans de recarregar.

El navegador avisa que la connexió no és privada

Causa El certificat és autofirmat: cap navegador el reconeix, però la comunicació sí que va xifrada.

Solució Accepta l'excepció en un laboratori; en producció cal un certificat signat.

El nom no resol al client

Causa Falta la línia a /etc/hosts del client, o té la IP equivocada.

Solució Afegeix-la amb la IP que doni ip -brief a al servidor.
